## №009 · 2026-11-28 · FBR RAM Downloader v0.1.2 + ComfyUI 0.45.0 · HBM OC 1053 MHz на V100 16GB: малый выигрыш, два uncorrectable ECC

Метео: Tesla V100-SXM2-16GB, Ubuntu 22.04.5, kernel 6.8.0-149-generic, driver 580.178.04, Ryzen 5 5600G, 74 GiB RAM, NVMe. Тесты одиночные, сервер в остальном idle. После OC-серии частота возвращена на сток, `v100-unlock.service` отключён.

Конфиг OC: [FBR RAM Downloader v0.1.2](https://github.com/FBR-ROM/FBR-RAM-Downloader), `v100-unlock apply` (877.5 → 1053.0 MHz, +20%, metered). Изменение volatile: reboot/restore возвращает сток.

Не-якорь: LLM-часть — client HTTP A/B со переключением частоты памяти, не `strata bench run` по протоколу якоря; image-часть — другой движок/нагрузка (ComfyUI + Qwen Image 2.1), не Strata. Цифры не смешивать с anchor-рядом.

### Успешное

- **HBM OC применился чисто.** `v100-unlock` поднял частоту до 1053.0 MHz, metered 1053.0, без ошибок применения; restore вернул 877.5 MHz. Повтор: см. `logs/v100-16gb-hbm-oc-qwen-image-21-2026-11-28.txt`.
- **LLM decode на Strata получил небольшой прирост.** 8 пар 400-tok decode, чередование 1053/877: 1053 mean 59.96 tok/s (median 60.25, σ 1.40), 877 mean 56.83 (median 57.80, σ 2.56), paired diff +3.14 tok/s (+5.52%). Prefill ~1223 tok, 3 пары: +1.52% (в шуме). Класс: client.
- **Qwen Image 2.1 int8 отработал на стоке 2048×2048.** ComfyUI 0.45.0, torch 2.14.1+cu126, `--lowvram`, 20 шагов, euler/simple, cfg 1. Stock A/B v2 (разные seed, без кэша): `--lowvram` 503.4 s, `--lowvram --fp16-vae` 538.4 s, `--lowvram --async-offload --fp16-vae --reserve-vram 1` 541.9 s, `--fp16-vae` 542.3 s. Все ok. Класс: engine (ComfyUI history exec_ms).

### Неудачное

- **Uncorrectable ECC при LLM concurrency на 1053 MHz** (class: железо/конфиг).
  - Что сломалось: во время 4×200 tok concurrency A/B запрос на 1053 MHz получил HTTP 503, Strata engine сообщил uncorrectable ECC и упал.
  - Как понять: в логе Strata/server — `uncorrectable ECC error` / 503; `nvidia-smi -q -d ECC` показывает рост uncorrected volatile/aggregate.
  - Что делать вместо: вернуть сток `v100-unlock restore`, перезагрузить для очистки volatile, не использовать 1053 MHz на этой карте.

- **Uncorrectable HBM DBE при ComfyUI 2048×2048 на 1053 MHz** (class: железо/конфиг).
  - Что сломалось: генерация Qwen Image 2.1 2048×2048 на 1053 MHz не завершилась; ComfyUI умер, GPU потребовала reset.
  - Как понять: dmesg Xid 48 (DBE framebuffer, physAddr 0x21d4ec20, FBPA 0 subpartition 1), Xid 171 (HBM uncorrectable DRAM), Xid 63 (page retirement, reboot to activate), Xid 154 (GPU Reset Required); `nvidia-smi` — volatile uncorrected 1, aggregate 2.
  - Что делать вместо: немедленно `v100-unlock restore`, остановить нагрузку, перезагрузить; оставить сток 877.5 MHz. Карту с aggregate uncorrected ECC считать деградировавшей до диагностики/замены.

- **Первый ComfyUI A/B был недействителен из-за кэша** (class: харнес).
  - Что сломалось: 4 конфига вернули ~668 ms exec_ms / 15.02 s wall — одинаково, потому что тот же prompt/seed/граф был закэширован ComfyUI.
  - Как понять: `exec_ms` < 1 s для 2048×2048/20 steps; одинаковые времена на разных конфигах.
  - Что делать вместо: менять seed/вход на каждый прогон; проверять, что `execution_cached` не покрывает рабочие ноды.

### Вывод (что понял сегодня; что остаётся необъяснённым)

- На этой V100 16GB HBM OC до 1053 MHz **технически применим, но практически опасен**: малый выигрыш в LLM decode (+~5.5% mean, большой разброс) и нулевой/отрицательный в проверенном ComfyUI-наборе, ценой двух uncorrectable ECC и роста aggregate с 1 до 2.
- Для Qwen Image 2.1 2048×2048 на 16GB V100 лучший из проверенных запусков — простой `--lowvram`; дополнительные флаги не ускорили.
- Остаётся необъяснённым: насколько повторяем +5.5% decode на другом workload/длинном контексте; есть ли стабильная промежуточная частота ниже 1053 (инструмент её не даёт); насколько деградировала HBM после page retirement. Без отдельной диагностики HBM OC считать неприемлемым.
